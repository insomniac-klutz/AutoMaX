## 1. Synthetic certifier validity (T1-synth, T1-forecast)

2,000 repetitions per cell. δ = 0.1 is split over m = 4 bands (δ_j = 0.025). Seeds are pre-registered (D21). Population risk is computed by Rao–Blackwell averaging (C6).

| (d) clustered units | group | 500 / 2,000 / 10,000 | 0.0010 | 0.0000 / 0.0000 / 0.0010 | α = 1% (25%), 2% (58%), 5% (85%) |

- **Vacuous cells.** Cells where a band is never certified are labelled vacuous and are not counted as passes. These are mostly the tight bands at small n_calib, and generator (b) at α = 0.5%, where even the oracle has no coverage.
- **Power.** It is low at tight bands: generator (a) never certifies α ≤ 1%. The start rule tests at about 1.25 × n_min committed units, where a single loss blocks certification (Q26).
- **T1-forecast shifted path (reported, not gated).** Miscoverage was 0.107 at both horizons, with 8% (h = 1) and 24% (h = 24) infinite intervals. Selective risk jumped from about 0.017 before the shift to about 0.16 after it, which shows why forecasting results are labelled `holdout_empirical` (D15).

## 4. How this run differs from the first one

The first gate run, at commit a54018a, gave the same certificates. The integration review then found that a watch slice on California's numeric target wrote calibration gold values into the certificate. Those local outputs were deleted, the code was fixed (e986e1e), and the gate was re-run on the same benchmark folds. This certified each benchmark partition a second time; since then the vault-wide partition ledger refuses that (Q28). The trivial models, bands, losses and seeds were not changed in response to any calibration result.
